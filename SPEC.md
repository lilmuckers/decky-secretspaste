# Local Vault Decky Plugin — Specification

## 1. Purpose

Provide an encrypted password vault accessible in Steam Game Mode via a DeckyLoader plugin, with pluggable storage backends (gopass or a built-in encrypted local vault).

The plugin enables:
- Create/list/delete secrets identified by labels
- Secure encryption at rest (GPG via gopass, or local symmetric encryption)
- One-click copy of secrets to the clipboard
- Automatic clipboard clearing after a configurable timeout

The design explicitly avoids:
- Cloud services or sync
- Remote password managers
- Autofill or form injection
- Displaying secrets in plaintext in the UI after save

---

## 2. Non-Goals

- Browser-style autofill
- Integration with hosted managers (LastPass, Bitwarden, etc.)
- Multi-device sync or sharing between users
- Clipboard history management beyond clearing the plugin’s own writes

---

## 3. Architecture Overview

```
┌──────────────────────┐
│ Decky Frontend (UI)  │
│  React / TypeScript  │
│  - Clipboard timer   │
└─────────┬────────────┘
          │ RPC
┌─────────▼────────────┐
│ Decky Backend        │
│  Python              │
│  - Vault backends    │
│    • gopass wrapper  │
│    • local encrypted │
└──────────────────────┘
```

Key principles:
- All storage is local; no cloud sync.
- Pluggable vault backends: gopass (GPG) or local encrypted file.
- Secrets are not displayed in the UI after saving.
- Clipboard clearing is best-effort after a configurable timeout (handled on the frontend).

### Frontend
- React

### Backend
- Python 3
- subprocess (for gopass)

## 5. Data Model

### Vault storage
- gopass backend
  - Secrets stored in gopass under `secretspaste/<id>`
  - Metadata (id, name, created_at) cached locally for listing
- Local backend
  - Secrets stored in an encrypted JSON file under the plugin data directory
  - Master key generated by plugin; optional user password wraps the master key (PBKDF2 + Fernet/AES)

### Plugin configuration

Stored in `config.json` under the plugin data directory:
```
{
  "clipboard_timeout": 20,
  "vault_backend": "gopass" | "local"
}
```

---

## 6. Backend Responsibilities

### 6.1 Vault backends

- Gopass backend shells out to `gopass` (`insert`, `show -o`, `rm`) and caches metadata locally.
- Local backend encrypts per-secret payloads in a local file using Fernet; optional password wraps the master key (PBKDF2).

### 6.2 Clipboard Handling

- Clipboard write/clear runs on the frontend via `navigator.clipboard`.
- A timeout (default 20s, UI range 3–180) replaces the clipboard with a blank string after copy.

### 6.3 Security Constraints

- Secrets are never logged.
- Secrets are not displayed after save; decrypted values are only returned for explicit copy.
- Clipboard clearing is best-effort and time-based on the frontend.
- Errors do not leak secret content.

---

## 7. Backend RPC API (current)

- list_secrets(): [{id,name,created_at}]
- add_secret(name: string, value: string)
- delete_secret(id: string)
- get_secret(id: string) -> {id,name,value|null}
- set_vault_backend(backend: "gopass" | "local")
- configure_local_vault(password: string)
- unlock_local_vault(password: string)
- set_clipboard_timeout(seconds: number)
- get_status(): {vault_backend, clipboard_timeout, local_status}

---

## 8. Frontend Responsibilities

- List entries by label
- Search / filter labels
- Copy button per entry
- Delete action with confirmation
- Backend selection and local vault password controls
- Add entry (no edit; delete/recreate)

Settings:
- Clipboard clear timeout (seconds), default 20, range 3–180
- Backend choice: gopass or local encrypted; optional local unlock password

---

## 9. UX & Safety Rules

- Secrets are never displayed once saved.
- Copy is explicit (no automatic copy).
- Clipboard timeout is visible and configurable.
- Destructive actions require confirmation.
- Local vault may require unlock before operations if password-protected.
